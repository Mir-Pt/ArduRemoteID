## 1. 系统规划

### 1.1 总体目标

在 ESP32-S3/C3 上实现一个独立 Remote ID 广播模块：
从飞控接收 OpenDroneID 数据（身份/位置/系统/操作员），转换为标准 ODID 消息，
通过 WiFi（NAN/Beacon）与蓝牙（BT4/BT5）四通道广播，并具备参数配置、Web 运维、
签名安全与 OTA 升级能力。

### 1.2 硬件平台

- 主控 ESP32-S3 / ESP32-C3（双模 WiFi+BLE）
- 外设：CAN 收发器（TWAI 1Mbps）、WS2812/GPIO LED、可选蜂鸣器与 CAN 控制引脚
- 12 种板型（见附录 B）

### 1.3 软件分层

```
┌──────────────────────────────────────────────┐
│ 应用主程序 RemoteIDModule.ino (setup/loop)    │
├──────────────┬───────────────┬───────────────┤
│  输入层       │  数据组装      │  输出层        │
│  Transport   │  set_data()   │  Transmitter  │
│  ├MAVLinkSerial│  (共享结构→   │  ├WiFi_TX     │
│  └DroneCAN    │   ODID_UAS_Data)│ └BLE_TX      │
├──────────────┴───────────────┴───────────────┤
│ 支撑层: parameters/webinterface/status/romfs/led/util │
│ 安全层: check_firmware/efuse/monocypher/secure_command │
│ 物理层: CANDriver(TWAI) / HardwareSerial        │
└──────────────────────────────────────────────┘
```

### 1.4 编译配置与板型体系

- **编译开关**（`options.h`）：`AP_DRONECAN_ENABLED`（= `defined(PIN_CAN_TX) && defined(PIN_CAN_RX)`）、
  `AP_MAVLINK_ENABLED`（恒 1）
- **板型宏**：构建时经 `build.extra_flags="-DBOARD_$* -DESP32"` 注入（`Makefile:75`），
  板型名映射到 `board_config.h` 中 `#elif defined(BOARD_xxx)` 分支
- **板型配置项**（`board_config.h:4-14`）：`BOARD_ID`、`PIN_CAN_TX/RX`、`PIN_UART_TX/RX`、
  LED 引脚、可选 `PIN_CAN_EN/nSILENT/TERM`、`BUZZER_PIN`、`CAN_APP_NODE_NAME`、`CAN_TERM_EN` 等

## 2. 数据流方向

### 2.1 端到端数据流

```
飞控 (ArduPilot / PX4)
  │
  ├─ DroneCAN ──► CANDriver.receive() ─► canardHandleRxFrame()
  │                 └─ onTransferReceived() ─► handle_Location/BasicID/... ─┐
  │                                                                         │
  └─ MAVLink ───► update_receive() ─► mavlink_parse_char() ─► process_packet() ─┤
                       └─ OPEN_DRONE_ID_*_decode() ─────────────────────────────┤
                                                                                │
                                                          ┌─────────────────────▼──┐
                                                          │ Transport 共享静态结构   │  (最后一帧生效)
                                                          │ location/basic_id/self_id │
                                                          │ system/operator_id/...    │
                                                          └─────────────────────┬──┘
                                                                                │
                                                          set_data() (RemoteIDModule.ino:201)
                                                          │  单位换算 + 校验 + PX4修复
                                                          ▼
                                                      ODID_UAS_Data UAS_data
                                                          │
                        ┌─────────────────────────────────┼──────────────────────┐
                        │              │                  │                      │
                 WiFi_TX.transmit_nan   WiFi_TX.transmit_beacon   BLE_TX.transmit_longrange   BLE_TX.transmit_legacy
                        │              │                  │                      │
                   NAN Sync+Action   Beacon Vendor IE    BT5 Coded PHY 整包     BT4 轮转单条
                        │              │                  │                      │
                        └──────────────┴──────────────────┴──────────────────────┘
                                          空中接收端 (手机 App / 地面站 / UTM)
```

### 2.2 两条输入分支

**DroneCAN 分支**：`DroneCAN::update()` → `processRx()` 每轮最多读 60 帧 →
`canardHandleRxFrame()` 解析与多帧重组 → 触发 `onTransferReceived_trampoline()` →
`onTransferReceived()` 按 `data_type_id` 分发 → `handle_Location()` 等用 `COPY_FIELD/COPY_STR`
宏把 `dronecan_remoteid_*` 结构拷入共享结构（`DroneCAN.cpp:599-709`）。

**MAVLink 分支**：`MAVLinkSerial::update()` → `update_receive()` 逐字节 `mavlink_parse_char()`
→ `process_packet()` 按 `msg.msgid` switch → `mavlink_msg_open_drone_id_*_decode()` 直接写入
共享结构并刷新 `last_*_ms`（`mavlink.cpp:133-295`）。

### 2.3 发射门控与时序

`loop()` 中四个发射器独立门控（`RemoteIDModule.ino:431-458`）：

| 发射器 | 门控参数 | 门控表达式 |
|---|---|---|
| WiFi NAN | `wifi_nan_rate` | `now_ms - last > 1000/rate` |
| WiFi Beacon | `wifi_beacon_rate` | `now_ms - last > 1000/rate` |
| BT5 Long Range | `bt5_rate` | `now_ms - last > 1000/rate` |
| BT4 Legacy | `bt4_rate` | `now_ms - last > (1000/bt4_states)/rate`（`bt4_states`=6/7） |

广播前置门控：`BCAST_POWERUP=1` 上电即播（无位置数据时置 SYSTEM_FAILURE）；
否则需至少收到一次位置数据才广播（`RemoteIDModule.ino:417-429`）。

## 4. 每个代码文件详解

> 每节按「功能 / 实现 / 原理 / 逻辑」四要素展开。

### 4.1 RemoteIDModule.ino（主程序）

- **功能**：固件入口，负责初始化、任务调度、数据组装与广播门控。
- **实现**：`setup()`（`58-135`）+ `loop()`（`364-462`）+ `set_data()`（`201-360`）+ `check_parse()`（`145-196`）。
- **原理**：协作式单线程轮询，`millis()` 软件节流，无 RTOS 抢占；编译期选择传输源。
- **逻辑**：
  1. `setup()` 依次初始化参数、LED、WiFi、串口、ODID 结构、MAVLink/DroneCAN、eFuse、OTA 校验。
  2. `loop()` 先轮询输入（`mavlink1/2.update()` + `dronecan.update()`），
     选主传输源（优先 MAVLink，否则 DroneCAN，都无则 `#error`）。
  3. 超时判定：位置/系统 5 秒未更新置 `ODID_STATUS_REMOTE_ID_SYSTEM_FAILURE`。
  4. `set_data()` 组装：BasicID（参数优先，飞控补齐）、OperatorID、SelfID、System、Location
     （含单位换算与 PX4 时间戳修复 `332-338`）。
  5. `check_parse()` 逐消息试编码，失败返回错误串，供 `arm_status_check` 与 LED 使用。
  6. 四发射器速率门控广播，`delay(1)` 省电。

### 4.2 options.h（编译开关）

- **功能**：编译期功能裁剪。
- **实现**：两个宏。
- **原理**：`AP_DRONECAN_ENABLED = defined(PIN_CAN_TX) && defined(PIN_CAN_RX)` —— 以引脚定义与否
  驱动协议编译，使无 CAN 板型（DB110/DB202）自动剔除 DroneCAN 代码。
- **逻辑**：`AP_MAVLINK_ENABLED` 恒 1，MAVLink 始终编译。

### 4.3 board_config.h（板级配置）

- **功能**：12 种板型的引脚与配置条件编译。
- **实现**：`#ifdef BOARD_xxx / #elif defined(BOARD_xxx)` 链，`#define BOARD_ID`、引脚宏。
- **原理**：构建注入单一 `BOARD_$*` 宏，只有匹配分支生效；引脚宏被 `options.h`、`.ino`、
  `led.h`、`CANDriver.cpp` 等多处消费。
- **逻辑**：当前激活 `BOARD_ESP32C3_DEV`（`19`）。每板型定义 CAN/UART/LED 引脚与可选
  控制引脚、节点名。CUAV 板额外定义 `CAN_TERM_EN LOW`（低电平使能）。

### 4.4 version.h / git-version.h（版本）

- **功能**：版本号定义。
- **实现**：`FW_VERSION_MAJOR=1`、`FW_VERSION_MINOR=14`（`version.h:2-3`）；
  `git-version.h` 由 `scripts/git-version.sh` 生成 `#define GIT_VERSION 0x<git描述>`。
- **原理**：编译前用 `git describe --always` 注入提交哈希，实现可追溯。

### 4.5 transport.cpp / transport.h（传输层基类）

- **功能**：定义共享 RID 数据、arm 状态检查、会话密钥生成、Ed25519 签名验证。
- **实现**：`arm_status_check()`（`43-118`）、`make_session_key()`（`123-137`）、
  `check_signature()`（`142-179`）。
- **原理**：
  - 共享静态结构实现「多协议最后帧生效」（`transport.h:69-71`）。
  - `arm_status_check()`：位置 ≤12s、其他 ≤22s 超时阈值（`49-50`，适配 PX4 0.1Hz）；
    SELF_ID/OP_ID/SYS 仅当飞控确实发送过才检查超时；位置为 (0,0) 视为无效。
  - `make_session_key()`：`{time_us, mac[8], rand}` 结构体经 CRC64 取 8 字节。
  - `check_signature()`：无公钥直接放行（`145-148`）；签名必须 64 字节；遍历 5 公钥做
    Ed25519 增量验证，签名覆盖 `sequence+operation+data[+session_key]`（`166-172`）。
- **逻辑**：签名验证在安全命令与固件校验中复用，是安全机制核心。

### 4.6 transmitter.cpp / transmitter.h（发射器基类）

- **功能**：WiFi/BLE 发射器公共接口。
- **实现**：`generate_random_mac()`（`transmitter.cpp:12-17`）逐字节 `random(256)`。
- **原理**：广播源 MAC 随机化，防止设备被长期追踪（ASTM 隐私要求）。

### 4.7 mavlink.cpp / mavlink.h + mavlink_msgs.h（MAVLink 传输）

- **功能**：通过串口收发 MAVLink 消息，解析 OpenDroneID 数据，发送心跳与 arm 状态。
- **实现**：`update()`（`48-80`）、`update_receive()`（`100-115`）、`process_packet()`（`133-295`）、
  `arm_status_send()`（`297-305`）、`request_odid_messages()`（`318-363`）。
- **原理**：
  - 双通道 `Serial1`(飞控)→COMM_0、`Serial`(USB)→COMM_1（`RemoteIDModule.ino:34-35`）。
  - MAVLink 2 + `all` 方言（含 OpenDroneID 与 ardupilotmega），`MAVLINK_MAX_PAYLOAD_LEN=255`。
  - 心跳自动学习飞控 `sysid`（`137-146`）。
- **逻辑**：
  1. `update()`：sysid 确认后发心跳 + 提频请求；每秒心跳 + arm 状态；50ms 流式发参数表。
  2. `process_packet()` switch 13 种消息，LOCATION/SYSTEM 按 timestamp 去重更新 `last_*_ms`。
  3. `request_odid_messages()`：`MAV_CMD_SET_MESSAGE_INTERVAL` 把 LOC/SYS 提到 2Hz、
     BASIC_ID 提到 1Hz，每 3 秒重发共 5 次（覆盖 PX4 启动窗口）。

### 4.8 mavlink_secure_command.cpp（MAVLink 安全命令）

- **功能**：处理经 Ed25519 签名保护的 SECURE_COMMAND 消息。
- **实现**：`handle_secure_command()`（`57-335`），6 种 operation。
- **原理**：`data[]` 同时承载 `数据 + 签名`（`data_length + sig_length ≤ 220`），
  先 `check_signature()` 验证再分发；防重放靠 `session_key`。
- **逻辑**：
  1. 长度校验 → 签名验证（失败 DENIED）。
  2. `GET_SESSION_KEY`/`GET_REMOTEID_SESSION_KEY`：`make_session_key()` 返回 8 字节。
  3. `GET_PUBLIC_KEYS`：`data[0]=起始索引, data[1]=数量`，按 32 字节逐个读回。
  4. `SET_PUBLIC_KEYS`：`data[0]=索引 + 连续 32 字节公钥`，逐个写入。
  5. `REMOVE_PUBLIC_KEYS`：按索引删除（置空）。
  6. `SET_REMOTEID_CONFIG`：NUL 分隔 `NAME=VALUE`，`strchr('=')` 切分后 `set_by_name_string()`。

### 4.9 DroneCAN.cpp / DroneCAN.h + dronecan_msgs.h（DroneCAN 协议栈）

- **功能**：DroneCAN 节点管理 + RemoteID 消息接收 + 参数/安全命令服务。
- **实现**：`init()`（`68-98`）、`update()`（`106-118`）、`onTransferReceived()`（`177-231`）、
  `shouldAcceptTransfer()`（`239-268`）、`handle_*()`（`445-958`）、`do_DNA()`（`531-579`）、
  `processTx/Rx()`（`297-348`）、`micros64()`（`430-438`）。
- **原理**：
  - libcanard v0.2，4096B 内存池；静态跳板函数经 `user_reference` 转发到 C++ 实例。
  - 接收过滤器 `acceptance_code=0x10000000<<3`，只收优先级 ≥16 的帧，过滤 ESC 高频消息（`86-89`）。
  - 节点 ID：`CAN_NODE` 参数固定，否则 DNA 动态分配（`94-96`）。
- **逻辑**：
  1. `update()`：DNA → 每秒 NodeStatus/ArmStatus → processTx → processRx。
  2. `onTransferReceived()` 按 `data_type_id` 分发 9 类消息；DNA 未完成时只处理 Allocation。
  3. `handle_Location/System` 按 timestamp 去重；`handle_param_getset` 支持全类型、锁定拒写、密码掩码。
  4. `handle_SecureCommand` 支持会话密钥与远程配置（与 MAVLink 侧对称）。
  5. `micros64()`：检测 32 位回绕累加高位，扩展为 64 位时间戳。

### 4.10 CANDriver.cpp / CANDriver.h（TWAI 底层驱动）

- **功能**：封装 ESP32 TWAI，提供 CAN 2.0B 帧收发与时序计算。
- **实现**：`init()`（`60-66`）、`send()`（`265-307`）、`receive()`（`315-333`）、
  `computeTimings()`（`150-254`）。
- **原理**：CAN 2.0B 扩展帧，1Mbps（`TWAI_TIMING_CONFIG_1MBITS`）；单过滤器模式；
  `tx_queue_len=5`、`rx_queue_len=50`、中断优先级 LEVEL2（`69-77`）。
  `computeTimings()` 依据 Koppe 论文求解 prescaler/BS1/BS2，采样点目标 87.5%。
- **逻辑**：`send()` 检查总线状态（STOPPED 重启、BUS_OFF 每 2s 恢复），5ms 超时；
  `receive()` 非阻塞 5ms 超时，自动设扩展帧标志，过滤错误帧。

### 4.11 WiFi_TX.cpp / WiFi_TX.h（WiFi 广播）

- **功能**：WiFi NAN 与 Beacon 两种模式广播 ODID。
- **实现**：`init()`（`22-59`）、`transmit_nan()`（`68-93`）、`transmit_beacon()`（`104-150`）、
  `dBm_to_tx_power()`（`158-167`）。
- **原理**：
  - `init()`：随机 MAC（本地管理位）+ SoftAP（Web 使能时 4 连接，否则 0）+ HT20 + 功率。
  - NAN：`odid_wifi_build_nan_sync_beacon_frame` + `odid_wifi_build_message_pack_nan_action_frame`，
    经 `esp_wifi_80211_tx` 直发。
  - Beacon：构建完整 Beacon 帧 → 跳过 58 字节头 → 封装为 Vendor IE（OUI `FA:0B:BC`、Type `0x0D`）
    → `esp_wifi_set_vendor_ie` 写 Beacon + Probe Response。
- **逻辑**：序列计数器 `send_counter_nan/beacon` 递增，供接收端检测丢包。

### 4.12 BLE_TX.cpp / BLE_TX.h（蓝牙广播）

- **功能**：BT4 Legacy 与 BT5 Long Range 两种模式广播 ODID。
- **实现**：`init()`（`109-154`）、`transmit_longrange()`（`164-194`）、
  `transmit_legacy()`（`208-375`）、`dBm_to_tx_power()`（`70-98`）。
- **原理**：
  - 双广播集（`BLEMultiAdvertising advert(2)`）：实例 0 = BT4 Legacy，实例 1 = BT5 Coded PHY。
  - BT5 首选 S8 编码（`147`），距离约为 BT4 的 4 倍。
  - 随机静态 BLE 地址（`mac_addr[0] |= 0xc0`）。
  - 帧头：BT5 `[len+5][0x16][0xFA 0xFF][0x0D][counter]`；BT4 `[0x1E][0x16][0xFA 0xFF][0x0D]`。
- **逻辑**：
  1. `transmit_longrange()`：`odid_message_build_pack()` 整包 + 帧头，一次广播。
  2. `transmit_legacy()`：`legacy_phase` 轮转 7 相位（Location/BasicID0/SelfID/System/
     OperatorID/BasicID1/设备名），每相位编码单条消息；单 ID 时 6 相位循环。

### 4.13 parameters.cpp / parameters.h（参数系统）

- **功能**：参数定义、NVS 持久化、公钥管理、初始化。
- **实现**：描述符表 `params[]`（`33-91`）、`init()`（`445-541`）、类型化 `set_*/get_*`、
  `set_by_name_string()`（`620-647`）、`get/set/remove_public_key()`（`662-746`）。
- **原理**：NVS `"storage"` 命名空间，写后即存；FLOAT 经 union 转 uint32 二进制存储；
  `TO_DEFAULTS=1` 触发 `nvs_flash_erase()+esp_restart()`。
- **逻辑**：
  1. `init()`：加载默认 → NVS 恢复 → 空 SSID 用 MAC 生成 `RID_xxxx` → 首次加载默认公钥
     （ArduPilot key1/2 + 板型相关 key3）→ BasicID 兜底（无飞控时用 MAC 生成 `ESP32-XXXX`）。
  2. 公钥以 `"PUBLIC_KEYV1:<base64>"` 存储，`get_public_key()` 校验前缀 + Base64 解码 32 字节。

### 4.14 status.cpp / status.h（状态 JSON）

- **功能**：为 Web AJAX 生成 RID 状态 JSON。
- **实现**：`status_json()`（`442-525`）+ 一组枚举映射表（`105-316`）+ 格式化辅助函数。
- **原理**：`json_table_t` 键值对 → `json_format()` 序列化；`ENUM_MAP` 宏查表把 ODID 枚举
  转可读字符串；`LatLonString`/`AltString` 处理无效值（返回 "UNKNOWN"）。
- **逻辑**：六大段（STATUS/BASICID/OPERATORID/SELFID/SYSTEM/LOCATION）共 31 个字段，
  覆盖 ODID 规范全部状态字段，双引号直接删除做简化转义。

### 4.15 webinterface.cpp / webinterface.h（Web 界面）

- **功能**：Web 服务器（静态资源 + 状态 JSON + OTA）。
- **实现**：`ROMFS_Handler`（`50-119`）、`AJAX_Handler`（`128-149`）、`init()`（`164-286`）、
  `update()`（`298-307`）。
- **原理**：ESP32 `WebServer`（80 端口）；静态资源走 ROMFS gzip 流（`Content-Encoding: gzip`）；
  AJAX 优先于 ROMFS 注册（`172-173`）。
- **逻辑**：OTA 三阶段回调——START 开 `Update.begin()`；WRITE 缓存前 16 字节 `lead_bytes` 并
  分块写入；END 写 `SPI_FLASH_SEC_SIZE+1` 个 0xFF 强制刷缓冲 → `check_OTA_next()` 验签 →
  通过则 `Update.end(true)`+重启，失败返回 500。**无写参数端点**。

### 4.16 romfs.cpp / romfs.h（只读文件系统）

- **功能**：内嵌 gzip 静态文件的查找与流式读取。
- **实现**：`find()`、`exists()`、`find_stream()`、`find_string()`（`108-160`）。
- **原理**：文件表在自动生成的 `romfs_files.h`（`make_romfs.py` 产出，`compresslevel=9,mtime=0`）；
  `ROMFS_Stream` 继承 Arduino `Stream` 供 `server.streamFile()` 流式发送。
- **逻辑**：`find_string()` 读 gzip 末尾 4 字节解压长度 → uzlib 解压（不校验 CRC 省 Flash）→
  返回字符串（用于加载公钥）。

### 4.17 check_firmware.cpp / check_firmware.h（固件签名验证）

- **功能**：OTA 固件的 Ed25519 签名与板 ID 验证。
- **实现**：`check_partition()`（`31-43`）、`check_OTA_partition()`（`53-110`）、
  `check_OTA_next()`（`118-136`）、`check_OTA_running()`（`142-151`）。
- **原理**：映像末尾追加 `app_descriptor_t`；`memmem` 搜反转魔数定位描述符；
  校验 `image_size` 与偏移一致；遍历公钥做 Ed25519 增量验证。
- **逻辑**：无公钥接受任意固件；`lock_level==-1` 跳过；`board_id!=0 && !=BOARD_ID` 拒绝；
  `check_OTA_running()` 启动时仅打印不拦截（软校验），真正拦截在 OTA 刷入路径。

### 4.18 efuse.cpp / efuse.h（eFuse 熔丝）

- **功能**：烧录 eFuse 禁用调试/下载接口。
- **实现**：`set_efuses()`（`55-80`）。
- **原理**：`lock_level>=2` 且存在未烧录位时，批量烧录 7 类 eFuse 位（DIS_DOWNLOAD_MODE 等）。
- **逻辑**：不可逆；烧录后 USB 刷写被永久禁用，仅能签名 OTA 升级。

### 4.19 led.cpp / led.h（LED 状态指示）

- **功能**：GPIO 或 WS2812 LED 的状态显示。
- **实现**：`init()`（`19-32`）、`update()`（`38-108`）。
- **原理**：WS2812 用 `Adafruit_NeoPixel`；四状态四色：INIT 蓝、PFST_FAIL 黄快闪、
  ARM_FAIL 红慢闪、ARM_OK 绿常亮；`now_ms/blink_ms & 1` 实现闪烁相位。
- **逻辑**：GPIO LED 在 ARM_OK 保持 `STATUS_LED_OK` 电平，其他状态 100ms 翻转；
  WS2812 双 LED 同步显示，每 50ms 刷新。

### 4.20 util.cpp / util.h（工具）

- **功能**：CRC64、Base64 编解码、MIN/ARRAY_SIZE 宏。
- **实现**：`crc_crc64()`（`18-39`）、`base64_decode()`（`51-87`）、`base64_encode()`（`95-126`）。
- **原理**：CRC64 多项式 `0x42F0E1EBA9EA3693`（ECMA-182），初始/最终取反；
  Base64 逐字符查表（嵌入式小数据量场景）。
- **逻辑**：`crc_crc64` 用于会话密钥生成；`base64_*` 用于公钥存储/传输。
