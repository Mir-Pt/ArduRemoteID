## 1. 引言

### 1.1 编写目的

本文档面向项目评审、归档与后续开发者，完整描述 ArduRemoteID 固件的需求、架构、
详细设计、构建、测试与部署方案。文档采用「反向推理」方法：不依据项目初期假设，
而是以现有代码、注释、文档与版本历史为唯一事实来源，逐条还原软件的真实设计意图与实现。

### 1.2 项目背景

**Remote ID（远程识别）** 是无人机的「电子车牌」制度。美国 FAA 与欧盟 EASA 均要求
无人机在空中广播可被公众接收的身份与位置信息，以实现空中交通管理（UTM）与公共安全。

- **美国**：FAA Remote ID 最终规则，合规手段（Means of Compliance）参照 **ASTM F3411**
  （Standard Specification for Remote ID and Tracking）与 **ASTM F3586-22**（广播发射端）。
- **欧盟**：EASA Remote ID 规则，要求广播 EU 分类体系下的身份、等级（Class C0–C6）与类别（OPEN/SPECIFIC/CERTIFIED）。

本固件即 ArduPilot 官方开源的 Remote ID **发射端（Transmitter）** 解决方案，
对接 ArduPilot/PX4 飞控，通过 WiFi 与蓝牙广播符合 ASTM F3411 的 OpenDroneID 数据包
（`README.md:1-13`）。

### 1.3 术语与缩略语

| 术语 | 全称 / 含义 |
|---|---|
| RID | Remote ID，远程识别 |
| ODID | OpenDroneID，开源的 Remote ID 数据格式与库 |
| DroneCAN | 基于 CAN 总线的无人机通信协议（原 UAVCAN） |
| MAVLink | 无人机地面站/飞控通信协议 |

| TWAI | ESP32 的 CAN 外设（Two-Wire Automotive Interface） |
| NAN | Neighbor Awareness Networking，WiFi Aware 邻居感知网络 |
| BLE | Bluetooth Low Energy，低功耗蓝牙 |
| NVS | ESP32 Non-Volatile Storage，非易失性存储 |
| eFuse | ESP32 一次性可编程熔丝 |
| OTA | Over-The-Air，空中升级 |
| Ed25519 | 基于 Curve25519 的数字签名算法 |
| UAS | Unmanned Aircraft System，无人机系统 |

## 2. 项目概述

### 2.1 产品定位

ArduRemoteID 是一款**独立的 Remote ID 广播模块固件**，运行于 ESP32-S3 / ESP32-C3
微控制器上。模块通过 CAN（DroneCAN）或串口（MAVLink）接收飞控下发的无人机身份与位置数据，
再通过 **WiFi（NAN / Beacon）** 与 **蓝牙（BT4 Legacy / BT5 Long Range）** 四种无线通道
广播符合 OpenDroneID 规范的 Remote ID 信息，供附近手机、地面站与 UTM 系统接收。

### 2.2 系统目标

1. **合规性**：满足 FAA Remote ID 的 ASTM F3586-22 发射端 Means of Compliance，兼容欧盟法规。
2. **双协议接入**：同时支持 MAVLink 与 DroneCAN 两种飞控连接方式，且可共存。
3. **四通道广播**：WiFi NAN、WiFi Beacon、BT4 Legacy、BT5 Long Range 四种广播模式独立可开关。
4. **安全防篡改**：提供参数锁定、固件签名验证、安全命令签名、eFuse 烧录等分级安全机制。
5. **可配置可运维**：30 余项运行参数可通过 DroneCAN/MAVLink 远程读写，Web 界面支持状态查看与安全 OTA 升级。

### 2.3 设计原则

- **协议镜像**：DroneCAN 的 remoteid 消息是 MAVLink OpenDroneID 消息的精确镜像，
  使双传输实现简单、数据模型统一（`README.md:74-75`）。
- **最后一帧生效**：所有协议写入同一份共享状态结构，最后收到的消息覆盖之前的（`transport.h:69-71`）。
- **协作式轮询**：不引入应用层 RTOS 任务与锁，全部逻辑运行于 Arduino `loop()` 单任务，
  以 `millis()` 软件节流实现周期行为，降低复杂性与功耗（`RemoteIDModule.ino:431-461`）。
- **安全分层**：参数锁 → 固件签名 → 安全命令签名 → eFuse 硬锁，逐级收紧（`README.md:189-238`）。
- **编译期可裁剪**：板型通过 `-DBOARD_$*` 宏注入，DroneCAN 仅在有 CAN 引脚的板型编译（`options.h:12`）。

### 3.3 硬件平台需求

- **主控**：ESP32-S3 / ESP32-C3（`README.md:15-16`）
- **CAN 收发器**：1Mbps bxCAN（如 TJA1051），接 CAN TX/RX 引脚（`README.md:45-46`）
- **LED**：普通 GPIO LED 或 WS2812 RGB LED（`led.h:2-6`）
- **可选**：蜂鸣器（DB210 PRO）、CAN 静默/使能/终端电阻控制引脚（`board_config.h`）
- 支持 12 种硬件板型（详见附录 B）

### 3.4 通信协议需求

- **DroneCAN**：libcanard（v0.2），CAN 2.0B 扩展帧，1Mbps，接受过滤器过滤高频消息（`DroneCAN.cpp:86-89`）
- **MAVLink**：MAVLink 2，`all` 组合方言，UART（Serial1）+ USB（Serial）双通道（`mavlink_msgs.h:20-38`）

### 3.5 广播需求

- **WiFi NAN**：同步信标帧 + Action 帧，`esp_wifi_80211_tx` 直发原始帧（`WiFi_TX.cpp:76-88`）
- **WiFi Beacon**：Vendor Specific IE 嵌入 SoftAP 的 Beacon/Probe Response（`WiFi_TX.cpp:119-143`）
- **BT5 Long Range**：Coded PHY S8，一次性完整 Message Pack（250 字节）（`BLE_TX.cpp:170-185`）
- **BT4 Legacy**：31 字节限制，轮转发送单条消息（`BLE_TX.cpp:223-354`）

## 5. 详细设计

### 5.1 主程序与任务调度

`setup()` 初始化顺序（`RemoteIDModule.ino:58-135`）：

1. 关闭欠压检测（`WRITE_PERI_REG(RTC_CNTL_BROWN_OUT_REG, 0)`）
2. `g.init()` 加载参数（NVS）
3. LED 初始状态 → 按需初始化 WiFi（Web 使能时）
4. 初始化调试串口 `Serial` 与 MAVLink 串口 `Serial1`
5. `odid_initUasData(&UAS_data)` 初始化输出结构
6. 初始化 MAVLink 双通道 / DroneCAN
7. `set_efuses()` 安全熔丝检查
8. `CheckFirmware::check_OTA_running()` 启动时固件校验
9. 可选 CAN 使能/静默/终端电阻/蜂鸣器引脚配置
10. 设置 `esp_log_level_set("*", ESP_LOG_DEBUG)` 与 OTA 有效标记

`loop()` 周期任务（`RemoteIDModule.ino:364-462`）：输入轮询 → 选主传输源 → LED 刷新 →
超时判定 → Web 更新 → `set_data()` 组装 → 广播门控 → 四通道速率门控发射 → `delay(1)`。
所有周期行为用 `millis()` 时间戳实现软件节流，无 RTOS 抢占。

### 5.2 数据模型

**共享状态结构**（`transport.h:72-88`）：所有 Transport 派生类共享的 `static` 成员，
包含 `location`/`basic_id`/`authentication`/`self_id`/`system`/`operator_id`（MAVLink 格式）
及各类消息的 `last_*_ms` 时间戳，遵循「最后一帧生效」。

**ODID 输出结构**（`ODID_UAS_Data`）：`set_data()` 将共享结构换算后填充，
包含 `BasicID[2]`、`Location`、`System`、`SelfID`、`OperatorID` 及各自 `*Valid` 标志。
单位换算：经纬度 `×1e-7`、速度/航向 `×0.01`（`RemoteIDModule.ino:316-340`）。

**PX4 兼容修复**：位置时间戳 >3600 秒（无 GPS 锁定时 PX4 发 UINT16_MAX）时强制置 0，
避免 `encodeLocationMessage()` 失败（`RemoteIDModule.ino:332-338`）。

### 5.3 输入层

**DroneCAN**（`DroneCAN.cpp`）：
- 节点 ID 由参数 `CAN_NODE` 固定或 DNA 动态分配（`DroneCAN.cpp:94-96,531-579`）
- 接受过滤器只接收优先级 ≥16 的帧，过滤 ESC 等高频高优先级消息（`DroneCAN.cpp:86-89`）
- 订阅 GetNodeInfo/RestartNode/BasicID/Location/SelfID/System/OperatorID/SecureCommand/param.GetSet（`DroneCAN.cpp:239-268`）
- 每秒广播 NodeStatus 与 ArmStatus（`DroneCAN.cpp:106-118`）

**MAVLink**（`mavlink.cpp`）：
- 双通道：`Serial1`（飞控）→ COMM_0，`Serial`（USB）→ COMM_1（`RemoteIDModule.ino:34-35`）
- 处理 13 种消息（`mavlink.cpp:133-295`）
- 主动提频：`request_odid_messages()` 每 3 秒发 5 次 `MAV_CMD_SET_MESSAGE_INTERVAL`，
  将 LOCATION/SYSTEM 提到 2Hz、BASIC_ID 提到 1Hz（`mavlink.cpp:318-363`）

### 5.4 输出层

**WiFi**（`WiFi_TX.cpp`）：
- NAN：`odid_wifi_build_nan_sync_beacon_frame()` + `odid_wifi_build_message_pack_nan_action_frame()`，
  经 `esp_wifi_80211_tx` 直发（`WiFi_TX.cpp:76-88`）
- Beacon：提取 ODID 载荷封装为 Vendor IE（OUI `FA:0B:BC`，Type `0x0D`），
  经 `esp_wifi_set_vendor_ie` 同时写入 Beacon 与 Probe Response（`WiFi_TX.cpp:119-143`）

**BLE**（`BLE_TX.cpp`）：
- BT5：`odid_message_build_pack()` 整包 + 帧头 `[len+5][0x16][0xFA 0xFF][0x0D][counter]`（`BLE_TX.cpp:170-185`）
- BT4：帧头 `[0x1E][0x16][0xFA 0xFF][0x0D]` + 计数器 + 单条编码消息，
  `legacy_phase` 轮转 7 相位（Location/BasicID0/SelfID/System/OperatorID/BasicID1/设备名）（`BLE_TX.cpp:223-363`）

### 5.5 参数系统

参数表定义于 `parameters.cpp:33-91`，共 30 项（另含条件编译的 `CAN_TERMINATE`），
持久化到 NVS `"storage"` 命名空间，写后即存。类型枚举见 `parameters.h:71-79`。
完整参数表见附录 A。

参数写入通道：
- DroneCAN `GetSet`：全类型支持，锁定时拒写，密码参数读时掩码（`DroneCAN.cpp:720-882`）
- MAVLink `PARAM_SET`：仅 REAL32 数值型（`mavlink.cpp:258-283`）
- 安全命令 `SET_REMOTEID_CONFIG`：签名保护的 NUL 分隔 `NAME=VALUE` 批量写入（`mavlink_secure_command.cpp:280-323`）

### 5.6 安全设计

**分级锁定 `LOCK_LEVEL`**（`README.md:189-238`）：

| 等级 | 含义 |
|---|---|
| -1 | 调试模式，跳过一切固件校验 |
| 0 | 默认：允许改参数；OTA 仅接受板 ID 匹配 + 有效签名 |
| 1 | 锁定参数：DroneCAN/MAVLink 改参数被拒，仅能通过签名安全命令 |
| 2 | 额外烧录 eFuse 永久禁用 JTAG/下载模式（不可逆） |

**Ed25519 签名**（Monocypher）：
- 固件签名：`sign_fw.py` 对映像签名，追加 `app_descriptor_t{sig,board_id,image_size,signature[64]}`（`check_firmware.h:25-30`）
- 安全命令签名：覆盖 `sequence + operation + data + session_key`（`transport.cpp:166-172`）

**防重放**：会话密钥由 `MAC + micros + random` 经 CRC64 生成 8 字节，
`GET_SESSION_KEY` 之外的所有命令签名都附带上次会话密钥（`transport.cpp:123-137,169-172`）

**公钥管理**：5 个槽位（`MAX_PUBLIC_KEYS=5`），NVS 中以 `"PUBLIC_KEYV1:<base64>"` 存储，
首次启动从 ROMFS 加载 ArduPilot/BlueMark/CUAV 默认公钥（`parameters.cpp:505-521`）。
**无公钥时签名校验直接放行**（`transport.cpp:145-148`）。

### 5.7 Web 与 ROMFS

- Web 服务器基于 ESP32 `WebServer`（80 端口），AP 地址 `192.168.4.1`（`README.md:149-150`）
- 三个端点：静态文件（ROMFS gzip 流）、`/ajax/status.json`（状态 JSON）、`/update`（OTA）（`webinterface.cpp:164-286`）
- **Web 界面只读 + OTA，无写参数端点**（参数修改走 DroneCAN/MAVLink/安全命令）
- ROMFS：静态文件 gzip 压缩（`compresslevel=9, mtime=0`）内嵌 Flash，由 `make_romfs.py` 生成 `romfs_files.h`（`make_romfs.py:22-58`）

### 5.8 OTA 固件更新流程

1. 客户端上传 `.bin` 到 `/update`
2. 缓存前 16 字节 `lead_bytes` 用于签名验证（`webinterface.cpp:231-240`）
3. 分块写入 OTA 分区；结束时写 `SPI_FLASH_SEC_SIZE+1` 个 0xFF 强制刷缓冲区（`webinterface.cpp:247-258`）
4. `CheckFirmware::check_OTA_next()` 验证签名与板 ID（`check_firmware.cpp:118-136`）
5. 通过则 `Update.end(true)` 并重启，失败返回 500（`webinterface.cpp:261-279`）

## 9. 风险分析

### 9.1 技术风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| PX4 ODID 消息率极低（0.1Hz） | 数据超时、LED 绿红交替 | 放宽超时阈值、主动提频请求、MAC 兜底 ID |
| WiFi NAN 兼容性窄 | 部分手机无法接收 | 同时提供 Beacon 模式（兼容性更广） |
| ESP32 TWAI 无硬件过滤 | 高频消息占满 CPU | 优先级位接受过滤器 + 每轮 60 帧上限 |
| BT4 31 字节限制 | 只能单条轮发 | 轮转相位设计 + BT5 整包互补 |

### 9.2 合规风险

- **DoC 责任**：厂商须向 FAA 提交符合性声明（`README.md:9-13`），配置不当可能不合规
- **地区差异**：美国/欧盟规则不同（BasicID 类型、EU 分类字段），需按目标市场配置

### 9.3 安全风险

- **公钥泄露**：无公钥时签名校验放行，需在生产部署时确保已写入公钥并锁定
- **LOCK_LEVEL=2 不可逆**：eFuse 烧断后无法回退，需谨慎操作
- **私钥保管**：私钥泄露将导致可伪造固件签名与安全命令
